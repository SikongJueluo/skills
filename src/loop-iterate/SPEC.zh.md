# loop-iterate

以上一圈的契约为基准核对结果，把暴露出来的摩擦修进环境，再衔接下一圈。

对照契约读代码改动、测试结果与执行记录，拿具体事实请人核对，不空泛地问哪里没做好。

业务返工要么并入下一圈契约，要么回到 `loop-discuss` 重立契约，不在复盘里顺手改业务代码。环境层面的修补，包括工具链卡点、测试盲区、项目规范的遗漏以及本套 skill 自身的缺陷，直接落盘，不拖到下一圈。

大圆只在新事实足以推翻原方向时才修正，否则明确维持不变。整理最新现状与遗留项作为新起点，转 `loop-discuss`。

## 复盘模板

复盘追加到上圈契约页 `docs/plan/<时间-最终目标>/<n-最小闭环>.md` 的末尾，不另建文档。原契约正文不动，事后发现定错的验收标准也记在复盘里，不回改，否则下一圈失去对照基准。

```markdown
## 复盘

### 预期对照
* 达标：<通过验收的产出>
* 未达：<差在哪里，原因是什么>
* 遗留：<并入下一圈的旧债>

### 环境与 Harness
* <已落盘或待执行的修补>

### 下一圈输入
* 大圆：<维持不变，或具体修正>
* 新起点：<下一步切入点>
```
