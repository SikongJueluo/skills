# 公网分享

除非用户明确要求发布 deck，并且理解结果是公网可达的，否则不要在这里做任何事。如果目标受众或托管方不明确，仅一句“能分享这个吗？”并不够；上传前先询问。

## 预检

1. 确定确切的上传集合。一个 deck 就是一个专用文件夹，包含 `index.html` 及其 `assets/`；绝不上传该文件夹的父目录、技能目录或家目录。
2. 列出文件并检查：`find <deck-dir> -type f`。不要包含 `.env`、密钥、私有笔记、未发布图片或无关文档。
3. 确认每个图片/字体引用都是相对路径或有意的远程地址，并在本地打开 deck 确认能渲染。
4. 说明托管在哪里、URL 是否公开，以及如何撤下。在执行上传命令前取得明确的同意。

## 以 Vercel 为例

不要全局安装 Vercel，也不要自动化登录。用户自己登录：

```bash
npx --yes vercel@latest login
npx --yes vercel@latest whoami
```

然后在文件夹之外，只部署该专用文件夹：

```bash
npx --yes vercel@latest deploy <deck-dir> --yes
```

`npx` 会为本次运行把 CLI 取到 npm 缓存中；它不会安装全局包。`--prod` 是另一个决定：询问用户要生产别名还是预览 URL。当用户要求撤下时，从 Vercel 控制台移除该部署。

其他静态托管同样可行。规则不变：只上传 deck 文件夹，验证 URL 与每个资源，并记录如何移除。

## 上传之后

- 打开在线 URL，在手机尺寸视口下检查字体、图片与导航。
- 报告 URL、上传的文件集合，以及撤下路径。
- 不要把本地文件路径描述为公网 URL；若未检查 URL，就不要仅凭命令退出状态声称部署成功。
