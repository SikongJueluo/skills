# 可编辑 PPTX 排障

当 HTML → PPTX 试点或审计发现不匹配时读这份。转换工作流（[editable-pptx.md](editable-pptx.md)）负责准备、验收与交付；本文件帮助定位失败的表示形式。下文路径与通道名称是候选转换器的示例，不是稳定 API。

## 诊断表示形式

对受影响的页面与元素，比对：

1. 源素材与准备好的 HTML 渲染。
2. 实测的文本/形状/媒体记录，包括边界、字体/文本段样式与预期输出通道。
3. PPTX 对象的 XML、关联/媒体，以及渲染结果。

找出证据首次分岔的阶段。若准备好的 HTML 有错，修正其导出状态。若记录有错，诊断测量；若记录正确但 XML 有错，诊断组装；若 XML 看似正确但查看器表现不同，排查字体与渲染器行为。当整个 deck 掩盖了原因时，用最小页面/元素探针。

## 截图污染与素材

| 症状 | 需收集的证据 | 应对 |
| --- | --- | --- |
| 卡片或透明 logo 出现意外的矩形背景 | 它实际的通道与捕获边界；捕获 PNG 的 alpha；祖先背景；最终图片位置 | 尽可能使用原生几何或原始素材。确需捕获时，隔离目标图层与边界。仅设 `omit_background` 不会移除祖先绘制的背景。移除阴影可能避开截图触发条件，但那改变了设计，也没有修复捕获隔离。 |
| 图注或标签出现两次 | 打开嵌入媒体查找烙进图片的文本；统计原生文本记录并检查重叠 | 每个前景标签只保留在一种表示形式中。即使文本只输出一次，截图也可能包含绝对定位的兄弟元素。仅隐藏后代文本可能无法把图片从其兄弟覆盖层中隔离。优先使用原始图片字节加原生图注。 |
| deck 用了 `<img>`，但 PPT 里是重采样的截图 | 追踪对象与其嵌入媒体的关系；比对源字节/尺寸；检查工具真实的图片路径 | 可用时选择嵌入源字节的路径。复现 `object-fit`、`object-position`、透明度与裁切，而不要把相邻文本烙进图片。仅改标签/class 不能证明复用了原始素材。 |
| 图片偏移、被拉伸或留白过多 | 源尺寸；元素边界；视口钳制前后截图裁剪框；PPT 图片边界与裁切 | 同时检查坐标换算与捕获框更新。保持宽高比并匹配预期裁切；避免用任意的逐页偏移来补偿。 |

## 缺失的几何与不想要的效果

| 症状 | 需收集的证据 | 应对 |
| --- | --- | --- |
| 时间轴的圆点、线条、空框或伪元素装饰消失 | 该元素是否产生了形状记录；实测非零边界；计算出的填充/边框；伪元素处理 | 用受支持的路径把简单几何映射为原生线条/形状。若引擎省略空元素，这是抽取缺口，而不是 PPT 画不出圆。内联 SVG 可能恢复画面却丢失几何可编辑性；据此归类。 |
| 箭头或被裁切的面板变成矩形 | `clip-path`/变换处理；原生几何或截图通道；最终形状路径 | 当原生箭头/自由多边形能表达设计时优先用它。工具的栅格回退不能证明 OOXML 无法表示该多边形。 |
| 本应平坦的 PPT 形状周围出现新阴影 | 显式形状效果与样式/主题引用，例如 `effectRef`；被引用的主题效果样式 | 在更改之前先确认这是非预期的继承效果。可用时采用受支持的显式无效果样式；一刀切地改所有主题引用会抹掉有意的设计。 |
| 简单图表变成一张图片 | 其标签、连接线与几何在最终 PPTX 中的表示 | 图表需要可编辑时使用原生对象。SVG 插入即使矢量，也不自动等于可编辑几何。对复杂图表，先就可接受的编辑范围达成一致。 |

## 文本、字体与坐标

| 症状 | 需收集的证据 | 应对 |
| --- | --- | --- |
| 标题在 HTML 中框很宽却丢失末尾字符 | 实测文本边界 vs. 元素边界；舞台变换/视口缩放；PPT 文本框范围、内边距、字号与换行 | 定位第一处宽度不匹配。先检查是否重复施加了缩放，或只施加到某些字段，再考虑加宽 CSS。文本框内边距、字形进位与断行也可能有关；不要从一个比值推断出普适原因。 |
| 文本或图片持续偏小或偏移 | 已知的创作坐标、渲染坐标、舞台平移/缩放与 PPT 单位 | 一次性归一化所有坐标。在较小视口测量的固定舞台 deck 需要一次逆变换或按单位尺度测量，而不是对个别对象做临时乘数。 |
| 细/中等文本变成常规/粗体 | 请求的字重/样式；解析出的字体文件内部名称与字重；选定的 PPT 字体；嵌入实例；渲染器可用字体 | 测试工具支持的确切静态字体实例/字体映射。粗体标志不等于任意 CSS 字重，但那也不意味着 PPT 无法表示所有非 400/700 文本。栅格化或描边文本是丢失文本编辑性，不是字体修复。 |
| CJK 字形缺失，或某查看器改变了换行 | 东亚/拉丁字体指派、实际字形覆盖、嵌入状态/权限，以及该查看器可用的字体 | 在目标应用中核实预期字体路径。安装字体可能解决查看器回退，但需要同意；仅嵌入不是跨查看器证明。 |
| 上标、标签或表格数值跳到另一行 | 文本段边界/基线；文本框分组/宽度；真实段落间距与对齐 | 保留原生文本段与足够边界，或使用独立的定位文本框。对表格考虑原生单元格。重复空格与 SVG 文本可能掩盖布局缺陷，同时削弱编辑性。 |

## 导出状态与陈旧证据

| 症状 | 需收集的证据 | 应对 |
| --- | --- | --- |
| 每页都出现铅笔按钮、导航或对话框 | 实际转换器使用的 URL/状态；固定定位节点；准备好的视图截图 | 在转换视图中应用 deck 导出契约。让非内容 UI 离开该视图，同时保留原始 HTML 的编辑行为。 |
| 计数器显示为零、图表不完整，或只找到一页 | 运行时就绪状态、最终状态处理、激活行为与测量时机 | 等待导出就绪状态，并通过 deck API 或已验证的适配器激活页面。仅关闭动画不会计算 JavaScript 组件的最终值。 |
| 修复似乎无效，或审计结果与输出不一致 | 源文件 vs. 复用的准备副本；缓存输入；命令/选项；最终 PPTX 与对比构建的身份 | 确认转换器消费的是已编辑的文件。使受影响的缓存测量/渲染失效；全局准备或工具改动需要相应的新证据。 |

## 记录结果

一条可复用的发现包含：症状、最小触发条件、工具版本、失败的表示形式、证据、所选补救措施，以及剩余的编辑/视觉代价。把确认的原因与假设分开。把 deck 专属的路径/页码留在任务报告中；先检查适用范围，再提升为通用规则。

触发本工作流的案例使用了本地的图片隔离与主题效果补丁。二者都不由本技能维护，且任一都可能在上游过时。当变通手段无法满足用户契约时，报告工具限制与可选方案，而不是静默降低验收标准或另起一个转换器分叉。
