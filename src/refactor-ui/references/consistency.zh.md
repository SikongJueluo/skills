# 一致性：一套系统，而非同一模板

一致性是一套稳定的角色语法，不是布局完全相同。关键在于：同类事物是否得到相同处理，不同处理是否表达了不同含义。

当反馈认为作品不一致、彼此无关、像拼接起来的几块内容，或用户明确表示不希望所有界面都共用一种布局时，阅读本文件。

## 1. 盘点角色

列出产物实际使用的角色及其处理方式：

- 页面或章节标题；
- 引导语、眉题或类别标签；
- 正文、强调文字和辅助文字；
- 图注、元数据、署名；
- 导航和进度提示；
- 主要和次要操作；
- 图像、插图及其边框；
- 提示框、引语、数字和状态标签。

对每个角色，记录出现位置及所有处理方式。反馈通常来自三种情况之一：同一角色采用多种处理；一种处理方式承担多种角色；不同处理暗示了实际上并不存在的含义。

## 2. 角色 → 处理方式 → 含义

- 同一角色使用同一处理方式；同一处理方式表达同一含义。
- 只有在差异表示真实区别时才合理，例如层级、内容类型、交互状态或叙事节拍。
- 位置也承载含义。锚定在内容栏内的标题，与置于全宽顶部横栏的标题，会被读作不同级别。级别相同时，采用同一规则；若差异是有意的，则要让区分系统化且可见。
- 图注不是标签，标签不是标题。不要为了方便让一种视觉样式同时承担两种职责。

测试方法：指向某个实例，问读者会从它的处理方式推断出什么。如果推断有误，角色语法就有问题。

## 3. 让变化有据可依

- 布局应跟随内容结构：比较采用并列，序列采用步骤，单一主张采用一个焦点元素，画廊采用网格。
- 交替变化——例如图像先左后右——可以形成合理节奏。只有在它暗示了不存在的区别或破坏阅读顺序时才有问题。
- 不同页面类型可以共享系统而不共用模板。系统是一套语法，不是紧身衣。
- 抹去必要差异的统一化同样是不一致：它把不同事物当成相同。

不要用“所有页面看起来不一样”作为理由，把每页强行塞进同一布局。应稳定角色规则，并让内容结构决定布局。

## 4. 标签是一种契约

- 一种标签样式只承担一种职责。如果同一种样式同时用于类别、问题、解释标签和行动号召，读者就无法解码，应拆分角色。
- 标签应提供标题没有的信息。重复标题内容的标签只是装饰。
- 标签集合保持精简：章节标签、状态标签、注释标签。如果还需要第四种，检查它是否其实应该是标题或正文。
- 实为操作的标签应看起来像操作，而不是元数据。

## 5. 不要只检查颜色 token

复用 token 不保证一致性。还要检查：

- **字体：** 字体家族、字号阶梯、字重、大小写、字距、行高。
- **颜色：** 语义角色——文字、弱化文字、强调色、语义色——而不只是共用十六进制值。
- **空间：** 间距尺度、组内与组间关系、对齐边缘。
- **形状：** 圆角、边框粗细、阴影、分隔线。
- **媒体：** 比例、裁切、衬底或边框、图注位置、署名样式。
- **交互：** 悬停、焦点、激活、禁用、图标样式、控件高度。

两个元素即便使用同一个 token，仍可能表达不同含义；两个角色即便使用不同数值，只要差异有系统性，也仍然可以协调。修复语义规则，而不只是变量。

## 6. 在范围内修复

- 编辑前先建立角色映射，然后修复造成反馈的离群样式和含义不清的角色。
- 不要把每个界面都套上模板，也不要重设已获认可的差异样式。
- 若产物没有稳定语法，只定义能覆盖其实际角色的最小规则，不要建立完整设计系统。
- 局部例外若承载含义，应保留，并说明它遵循的规则。
- 不要把推断出的规则变成永久项目惯例。只有用户采纳后才记录。

## 7. 完成检查

- 任选同一角色的三个实例，读者都能预测它们的处理方式。
- 任选三种不同处理方式，都能说出每个差异的含义。
- 反馈中特定的不一致已消除；无关界面未被重新设计。
- 密度、布局、图像和节奏等合理变化仍然保留。
- 每个标签只承担一种职责。

## 避免

- 让每个页面都完全一样。
- 对不同级别的标题使用同一种字号。
- 只增加 token，却保留互相冲突的语义。
- 只修一个实例，却让其他同角色实例继续不一致。
- 把任何布局差异都叫作不一致。
