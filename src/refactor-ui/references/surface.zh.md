# 视觉表面：什么内容该放在这里

视觉表面是受众一次能看到的范围。上面所有元素都在争夺同一份注意力。大多数“太复杂”的反馈，源于同时承担太多职责，而不是像素太多。

当反馈涉及数量、密度、目的是否清楚、重复或交互操作的显著性时，阅读本文件。

## 1. 明确视觉表面的职责

用一句话说明职责：理解一个主张、作出决定、完成任务、比较选项，或体验一个瞬间。“展示该主题的一切”不是职责。

- 一个视觉表面承担一个主要职责。若两个职责确实同等重要，拆分视觉表面，或将它们排成先后顺序。
- 若媒介不能拆分，例如弹窗、单一屏幕或一张幻灯片，则保留服务于用户下一步行动的职责，把另一个放到较低层级。
- 不同视觉表面可以承担不同职责，不要让整个产物承担同一个职责。

测试方法：如果去掉所有并非履行职责所需的内容，会剩下什么？剩下的就是候选核心内容。

## 2. 把内容放到合适的层级

内容可放在四个层级：

1. **主要内容**——视觉表面所服务的主张、决定或操作。
2. **支持内容**——让受众能够信任主要内容或据此采取行动所必需的一两项信息。
3. **按需查看**——细节、定义、边界情况、历史、设置和次要操作。可以用工具提示、可展开区域、详情视图、次级面板、附录或备注文件。
4. **表面之外**——演讲讲稿、时间安排、主持提示、实现备注和提醒。

先将内容移到较低层级，再考虑删除。只删除在任何层级都没有职责的内容。

- **演讲或演示。** 受众一边看一边听。视觉表面给出主张，讲者负责说明。除非演示文稿明确是可自行阅读的讲义，否则把完整说明和“向现场提问”等提示放进备注。
- **阅读文档。** 没有讲者辅助读者。保留解释，但要建立层级和分组。
- **应用或工具。** 显著性取决于频率和后果。低频设置和破坏性操作可收进菜单，但必须保留可见入口。
- **参考资料。** 高信息密度本身就是目标。保留数据，改进分组、对齐和浏览顺序。

## 3. 检查重复

承担相同职责的两个区块会相互竞争。应合并两者，或移除其中一个。

常见形式：

- 标题和结论分别用不同说法表达同一件事；
- 标签标示了标题已明确表达的类别；
- 说明段落重述主张；
- 结尾总结重复了观众刚看过的内容；
- 说明文字之所以存在，只因设计不清楚——先改进设计，再删说明。

重复也可能承担叙事职责：开头的问题在结尾得到回答、反复出现的主题句，或以回顾本身为重点。保留在时间或顺序上能产生效果的重复；删除在同一视图中相互竞争的重复。

测试方法：遮住待判断的区块。视觉表面还能表达同一个要点吗？如果可以，该区块要么有不同职责，要么可以移除。如果不行，它就在传递含义，应保留并弱化。

可选不等于竞争。职责不同的副标题、图注、署名或注释，即使可以不放，也应保留。不要设置统一的字数限制或删减比例；已经安静的视觉表面，不会因为变得更安静而改善。

回顾若只是重述已有主张，就是重复；若增加综合判断、决定或后果，就是新内容。只重复前面页面的结尾页可以删；把反复出现的内容推导为结论的段落是一段论证，而非简单回顾。

## 4. 编辑文案，不重写论点

- 合并承担相同职责的句子。
- 将一个段落压缩为一个主张加一项支持信息。
- 删去铺垫、含糊措辞和元叙述，例如“本页将会……”。
- 保留作者口吻、事实、限定条件和含义。标明推断，不要编造更顺畅的事实。
- 优先用具体名词和动词。不要把每行都改成口号；口号会降低精确度。
- 署名、许可证和法律文字必须保留，并使用低调、稳定的样式。

删除独立论点或改变主张属于改变含义，必须确认。压缩和迁移不属于改变含义。

## 5. 密度不等于复杂度

表格、仪表盘、参考文档、日程、数据丰富的界面及详细阅读材料，都可能需要高密度。

- 复杂度来自同时竞争的决定数量，不是像素数量。
- 用分组、对齐、层级和渐进披露调整密度。不要把字号缩到不易阅读，也不要藏起用户需要的数据。
- 若内容仍溢出，拆分视觉表面，或把细节放到较低层级。靠缩小字号来塞下内容，不是布局设计。
- 稀疏的视觉表面如果没有足够信息让人行动，也是不合格的。目标不是留空。

视觉表面既密集又杂乱时，按用户下一步要做的事建立浏览顺序，再决定用什么来呈现数据：

- 把会改变判断或下一步行动的信息置于首读层，把常规背景数据集中在紧凑的列表或表格中。仅按数据类别分组，并不能解决所有区块同等抢眼的问题。
- 逐个检查卡片、徽章和迷你趋势图：遮住它之后，原有信息是否仍能读到？把只重复已有信息的元素合并或移除；如果图形独自表达了有用的变化或趋势，就保留它，或用能传达同一信息的方式替代。
- 合并承担同一职责的容器，用分隔线、对齐和字重建立层级，把最强的强调留给用户最先要看的信号。

### 运营仪表盘：先看需要处理的事

根据用户任务以及已有的状态、阈值或告警确定优先级。运营人员需要先判断是否介入时，先呈现异常和待处理事件，再用紧凑形式呈现稳定指标。保留每个必需数值和事件记录，让常用筛选和主要操作仍容易找到并使用。对照同尺寸的基线检查：第一眼能否辨认需要关注什么，其余数据与操作是否仍然容易找到？

## 6. 调整交互操作的显著性

当反馈针对用法而非外观时：

- 重现任务，找出用户迟疑、误读或回头的位置。观察实际操作路径，不能只看截图。
- 主要操作必须可见且容易辨认。降低次要操作的显著性，但不要把它们藏起来。
- 渐进披露需要可见入口和易发现的标签。藏起功能不等于简化。
- 保留键盘访问、焦点状态、标签、错误提示、撤销和恢复。
- 流程问题不是样式问题。改变顺序、默认项或可供性，不要只改颜色。

## 7. 完成检查

- 新用户能说出要点或下一步操作。
- 每个可见区块都有不同的职责；同一视图中没有两个区块在做同一件事。
- 每个移动或删除的区块都已放到另一个层级，或明确属于有意删除。
- 高密度视觉表面仍易浏览；低密度视觉表面仍提供足以行动的信息。
- 必需的事实、指令、署名和功能都未丢失。

## 避免

- 按统一百分比删减每个视觉表面。
- 通过缩小字号让内容塞得下。
- 藏起核心功能以显得简单。
- 因为署名或限定说明影响美观而删除它们。
- 把“每页一件事”套用到需要完整阅读的材料上。
- 把说明换成含糊口号。
